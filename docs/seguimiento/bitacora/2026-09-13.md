### Ajuste posterior: una unica entrada principal

A peticion del usuario, main.py raiz ahora crea la aplicacion con
`app = create_app()`. Se elimino el bloque de arranque directo de Python y la
instancia global del modulo interno. Este conserva la factoria para no duplicar
rutas, middleware ni manejo de recursos. La configuracion compartida y las guias
usan `main:app`. No se agregaron CORS ni migraciones automaticas del ejemplo.
Verificacion de este ajuste: 6 pruebas de entrada y API correctas; no se repitio
la suite de integracion PostgreSQL en este cambio de punto de entrada.

Tras recibir una captura de la configuracion FastAPI **Cognitive**, se documento
como conservarla: Application name `app`, directorio raiz e interprete `.venv`.
No depende del bloque de ejecucion directa de Python. No se modifico el estado
en memoria del IDE ni se afirmo haber pulsado Run. Se agrego una
[lista de dependencias del usuario](../planificacion/lo-que-necesito.md), separando
credenciales locales, decisiones de producto y desarrollo posible sin claves.

La conexion directa a la base real necesita COGNITIVE_DATABASE_URL en .env segun
el ultimo estado conocido. No hay worker, LangGraph, embeddings, chat RAG ni
busqueda vectorial ejecutandose. Tambien faltan invitaciones, recuperacion de
contrasena, verificacion de correo y administracion de miembros.

No se configura una automatizacion diaria: las nuevas entradas se mantienen
siguiendo [COMO_ACTUALIZAR](../COMO_ACTUALIZAR.md).
